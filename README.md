# Приём заявок с сайта и передача в CRM (Битрикс24)

Небольшой сервис на TypeScript и Node.js. Принимает заявки из формы на сайте, убирает дубли клиентов, передаёт заявки в CRM, повторяет отправку при сбоях и показывает менеджерам, что произошло.

## Какую проблему решает

- Заявки с сайта вводили в CRM вручную, часть терялась.
- Один и тот же клиент попадал в CRM несколько раз.
- Если CRM была недоступна, заявка пропадала.

## Что умеет

| Возможность | Как сделано |
|---|---|
| Приём заявок | `POST /api/lead` (JSON или обычная HTML-форма) |
| Проверка данных | имя, телефон или почта; телефон приводится к виду `+7XXXXXXXXXX` |
| Защита от ботов | скрытое поле-ловушка `website` и ограничение 10 заявок в минуту с одного адреса |
| Дубли | поиск по телефону и по почте; повторная заявка объединяется с прежней и обновляет тот же лид в CRM |
| Надёжность | заявка сначала сохраняется в базе, потом уходит в CRM; при сбое повторные попытки с растущей паузой (1, 2, 4, 8 минут, максимум 5 попыток) |
| Журнал | все события пишутся в таблицу `logs` и показываются менеджерам |
| Страница менеджеров | список заявок, статусы, ошибки, кнопка «Повторить отправку», пароль по желанию |
| CRM | `BitrixClient` (входящий вебхук, REST API) и `MockCrmClient` для запуска без Битрикс24 |

## Запуск на macOS

Нужен Node.js 22.5 или новее (`brew install node`).

```bash
cd crm-leads
npm install
cp .env.example .env
npm start
```

Откройте http://127.0.0.1:3000/ (заявки) и http://127.0.0.1:3000/demo (тестовая форма).

Пример запроса:

```bash
curl -X POST localhost:3000/api/lead \
  -H 'Content-Type: application/json' \
  -d '{"name":"Иван","phone":"8 (900) 123-45-67","message":"Оклейка фургона"}'
```

Отправьте то же самое с телефоном `+7 900 123 45 67`: в ответе будет `"duplicate": true`, а в CRM останется один лид.

Чтобы увидеть повторные попытки, задайте в `.env` `MOCK_FAIL_RATE=0.7` (70% запросов к тестовой CRM будут «падать»).

## Подключение к настоящему Битрикс24

1. В Битрикс24: Разработчикам → Другое → Входящий вебхук, права на CRM.
2. Скопируйте адрес вида `https://ваша-компания.bitrix24.ru/rest/1/xxxxxxxx/` в `BITRIX_WEBHOOK_URL`.
3. Перезапустите сервер. Заявки пойдут в методы `crm.lead.add` и `crm.lead.update`.

Внимание: клиент Битрикс24 написан по документации REST API, но на реальном портале я его не проверял. Сначала попробуйте на бесплатном тестовом портале.

## Тесты

```bash
npm test
```

12 тестов проверяют: нормализацию телефона, валидацию, отправку, дубли (в том числе в разных форматах телефона), сбой CRM и повторные попытки, переход в статус «ошибка» и ручной повтор, защиту от двойной отправки, защиту страницы паролем, экранирование HTML, ограничение частоты.

## Устройство

```
src/
  validate.ts   проверка и нормализация данных формы
  db.ts         схема SQLite (таблицы leads и logs)
  crm.ts        интерфейс CrmClient, BitrixClient, MockCrmClient
  service.ts    вся бизнес-логика: дубли, отправка, повторы, журнал
  app.ts        HTTP-сервер: маршруты, пароль, лимиты, CORS
  ui.ts         HTML страницы менеджеров и тестовой формы
  index.ts      запуск и таймер повторных попыток
test/           тесты
```

Заявка проходит так: форма → `validateLead` → `accept` (сохранение, поиск дубля) → ответ сайту → `sync` в фоне → CRM. Если CRM не ответила, заявка остаётся в статусе `pending`, а таймер раз в 30 секунд вызывает `retryDue`.

## Решения и ограничения (о чём можно рассказать на собеседовании)

- **Сначала база, потом CRM.** Сайт получает быстрый ответ, а заявка не теряется, даже если CRM лежит.
- **Интерфейс `CrmClient`.** CRM можно заменить или подменить в тестах, не трогая остальной код.
- **Дубли ищутся по нормализованным данным.** Иначе `8 900...` и `+7 900...` считались бы разными клиентами.
- **Известное слабое место:** если CRM приняла лид, но сервис упал до записи ответа в базу, при повторе в CRM может появиться второй лид. Полное решение требует проверки по `crm.duplicate.findbycomm` перед созданием.
- **Один процесс.** Защита от двойной отправки и лимит частоты хранятся в памяти. Для нескольких серверов нужна общая база или очередь (например, Redis).
- **Лимит частоты считается по адресу соединения.** За прокси (nginx) нужно учитывать заголовок `X-Forwarded-For`.
- **Страница менеджеров** слушает только `127.0.0.1` и по умолчанию без пароля. Перед публикацией задайте `ADMIN_PASSWORD` и используйте HTTPS.
- **Десять цифр в телефоне** считаются российским номером без кода страны.
- **Нет** миграций базы, очереди сообщений, ролей пользователей и автотестов интерфейса.

## Что отвечать, если спросят «а на PHP?»

Логика переносится один к одному: `validate` и `service` превращаются в классы, SQLite заменяется на MySQL, `CrmClient` остаётся интерфейсом. Для Битрикс24 те же вызовы `crm.lead.add` и `crm.lead.update` делаются через `curl`.
